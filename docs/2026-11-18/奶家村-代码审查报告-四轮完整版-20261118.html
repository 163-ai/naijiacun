「奶家村」代码审查报告

  • 仓库：https://github.com/163-ai/naijiacun
  • 审查时间：2026-11-18
  • 审查范围：全部 120 个文本文件（约 2.3 万行 JS）、Node 服务、Cloudflare Worker、浏览器扩展、C# 桌宠、CI 脚本
  • 审查方式：静态分析 + 关键问题本地复现验证

总体评价

项目工程化程度较高：模块划分清晰、有 CI、有测试、密钥管理规范（全部走环境变量/localStorage，仓库内无硬编码真实密钥）、前端 XSS 防护到位（统一 escapeHTML 转义 + 消息渲染用 textContent）、Worker 有限流和 KV 队列设计。

发现的问题集中在三类：服务端健壮性（含 1 个可远程打挂服务的 P0）、构建脚本必然失败、游戏逻辑边界 bug。以下按优先级排列。

🔴 P0 — 必须立刻修（可远程致服务瘫痪）

1. server.js:84 — 单次请求即可打挂整个服务

decodeURIComponent 未捕获 URIError。Node 在 http 回调里抛未捕获异常会直接终止进程。

const decoded = decodeURIComponent(urlPath.split("?")[0].split("#")[0]); // ← 无 try/catch

触发：服务监听 0.0.0.0，任何人 GET /%（任意非法 % 序列）即可让全站下线，无需认证。 已实测复现。 修复：

let decoded;
try { decoded = decodeURIComponent(urlPath.split("?")[0].split("#")[0]); }
catch (e) { return null; }

🟠 P1 — 高优先级（功能错误 / 构建失败 / 资源滥用）

2. desktop/windows/build.ps1:61-62、verify.ps1:26 — 打包脚本必然失败

脚本复制并校验 使用说明.txt，但该文件不在仓库中（只存在于已打包的 zip 里），而 $ErrorActionPreference='Stop' 会让 Copy-Item 报错即中止。README.md:15 还声称包里有它。 修复：把 使用说明.txt 加入版本控制，或在 build.ps1 里先生成。

3. server.js:212 — 给 const 重新赋值，异常时二次崩溃

第 186 行 const encoding = ...，第 212 行 catch { ... encoding = "identity"; } 给 const 赋值会抛 TypeError。压缩一旦抛错，catch 内再次抛错且无人捕获，同样打挂进程。 修复：第 186 行改为 let encoding。

4. serve.js:39 — 前缀比较绕过导致目录穿越（已实测复现）

filePath.startsWith(ROOT) 只做字符串前缀判断，无目录分隔符边界。 触发：/../naijiacun-main-evil/secret.txt 解析后仍以 ROOT 字符串开头，可读取同前缀兄弟目录任意文件。 修复：if (filePath !== ROOT && !filePath.startsWith(ROOT + path.sep))。

5. server/tts-worker.js:228 /api/chat — 开放的 LLM 代理，可被无限白嫖

handleChat 的 key 逻辑：x-llm-key 请求头 || env.LLM_KEY。访客不带 key 时直接用站长的 Key；且该端点没有任何配额限制（对比 /api/sf-tts 有 bumpQuota）。CORS 白名单只挡浏览器，服务端脚本可随意伪造 Origin 直连。 风险：任何人可无限调用消耗站长 LLM 额度。 修复：给 /api/chat 加与 SF TTS 相同的按 IP 限流；或去掉 env.LLM_KEY fallback，强制访客自带 key。

6. js/kof.js:789-798 — 捕捉判定与 KO 不同步，输了也能判赢

tryCatch() 的 setTimeout(..., 420) 回调只检查 Fight.on，不检查是否已 KO / 回合结束。 触发：敌人残血时投球，420ms 内被 KO，endRound("capture") 抢先执行，把失败判成收服成功并发奖励。 修复：回调加 if (!Fight.on || phase !== "fight" || roundEnded) return;，并在 Fight.start/finish 里 clearTimeout。

7. js/game2d.js:5490-5519 — 钓鱼第 8 竿后可无限刷捕捉球

第 8 竿后仅用 setTimeout(closeFishing, 900) 延迟关闭，fishing.on 仍为 true，期间重复按键继续 fishing.rods++ 且每次 state.balls += 1。 修复：函数开头加 if (!fishing.on || fishing.rods >= FISH_RODS) return;，第 8 竿立即置 fishing.on = false。

  • "八个角色过时"是误判：README 那处指音色数量（8 个），正确；只修了真正过时的"六个角色"。
  • "图鉴写死 /8 是 bug"是误判：游戏图鉴 DEX_ORDER 恰好 8 位（不含 naicha/xiaocao），写死 8 正确。
  • 3d-data.js 删除：见第三轮说明——浏览器根本不下载它，运行时零影响，删除不可逆，仅给建议。

后续发展建议（需你决策，未擅自改）

按投入产出比排序。前 3 项建议优先做。

P0 · 建立质量安全网（最高优先）

  • 补第一批核心单测：game2d.js（6606 行）、chat.js、tts.js 额度逻辑、data.js 字段校验目前零测试。CI 已就位，但只有扩展的 7 个测试。建议先给「额度计算 / 聊天配置合并 / 数据字段完整性」写 10\~15 个单测——这是内容型站点防白屏最有效的一步。
  • 游戏页 WebGL 初始化加降级：game2d.js:244 顶层 new WebGLRenderer 无 try/catch，无 WebGL2 的设备会模块求值中断 → 标题页按钮全失效（实质白屏）。pet3d.js:35-40 已有正确范式，照搬即可。这是线上最可能的白屏点。
  • 全局错误可观测性：全站无 window.onerror / unhandledrejection 监听，线上崩溃静默发生、维护者无从发现。建议加一个统一监听，至少 console.error + 可见提示，有条件打到自建采集端点。

P1 · 消除配置与兼容性风险

  • 额度默认值对齐：DEPLOY-LLM.md 说 40、代码 120。你定一个值后统一代码/文档，并在 CI 加一致性断言。
  • importmap 兼容声明：裸说明符 import "three" 依赖 importmap，Safari \<16.4 / Chrome \<89 会整链崩溃。建议 README 声明最低浏览器版本，或改显式相对路径 import。
  • 默认代理单点：聊天/TTS/群动态全指向同一 workbuddy.host，挂了就全失效。建议内置 2+ 可切换节点，失败自动轮询（地址已在 E1 收敛到 config，改造成本降低）。
  • 群页 showModal 兼容回退：group.js 直接调 dlg.showModal()，chat.js:816 已有 if (showModal) ... else setAttribute("open") 的回退范式，复用即可。
  • 窄屏工具栏 / 横屏虚拟键溢出：css/game.css 在 320–640px 宽和横屏 \<430px 高时按钮溢出、虚拟键重叠。加断点规则（flex-wrap / 缩小摇杆 / 靠两侧排列）。

P2 · 工程卫生与内容运营

  • 补 LICENSE：README 自述"暂未设置许可证"，与"吸引贡献者"的目标冲突。需你选定授权方式（如 MIT，排除第三方素材）——这是法律决策，未擅自加。
  • 配置双写治理：window.showTTSNotice 在 3 个页面各定义一次（依赖加载顺序）、19 处 window.* 全局赋值。建议收敛为 CustomEvent 或单个命名空间对象。
  • 依赖与产物治理：删除废弃的 vendor/three.min.js（零引用）、生成 vendor/manifest.json（版本/license/SHA）、确认扩展 dist/ 是否该入库（与源重复 7MB）。
  • 文档与结构补全：README 功能表/结构树缺游戏页、群聊页、浏览器扩展、C# 桌宠四大模块；"纯静态零依赖"表述掩盖了 Node 服务/Worker/扩展的真实栈。
  • SEO 进阶：全站缺 og:\* / canonical（社交分享无预览卡）；主体内容纯 JS 渲染，爬虫/分享抓取器看到空白页。建议构建期预渲染核心内容或加 <noscript> 摘要。
  • 可访问性进阶：游戏页 7 个 overlay 非 dialog、无焦点管理；app.js 的 focus trap 只对盲盒弹窗生效（其余 4 个 Tab 逃逸）；桌宠仅指针拖拽、键盘无法移动。建议做一轮系统性的键盘可操作改造。
  • 资源加载降级：game2d.js 模型失败只写 console，无用户提示（3D 展台页已有完整 fallback UI，可复用）；CSS :has() 无回退（旧浏览器 toast 错位）。

建议的推进节奏

  • 第一步：做 P0 的 1+2（单测 + WebGL 降级），CI 才能真正发挥作用，白屏风险大幅下降。
  • 第二步：P1 的 4+5（额度对齐 + 浏览器兼容声明），消除"按文档操作却失败"的挫败。
  • 第三步：P2 里挑影响贡献者体验的（LICENSE、文档补全），降低参与门槛。
  • 其余按需穿插，不必一次做完。
