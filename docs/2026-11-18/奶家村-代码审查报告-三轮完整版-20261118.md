## 🔴 P0 — 必须立刻修（可远程致服务瘫痪）

### 1. `server.js:84` — 单次请求即可打挂整个服务

`decodeURIComponent` 未捕获 `URIError`。Node 在 http 回调里抛未捕获异常会直接终止进程。

```js
const decoded = decodeURIComponent(urlPath.split("?")[0].split("#")[0]); // ← 无 try/catch
```

**触发**：服务监听 `0.0.0.0`，任何人 `GET /%`（任意非法 `%` 序列）即可让全站下线，无需认证。
**已实测复现**。
**修复**：

```js
let decoded;
try { decoded = decodeURIComponent(urlPath.split("?")[0].split("#")[0]); }
catch (e) { return null; }
```

## 🟠 P1 — 高优先级（功能错误 / 构建失败 / 资源滥用）

### 2. `desktop/windows/build.ps1:61-62`、`verify.ps1:26` — 打包脚本必然失败

脚本复制并校验 `使用说明.txt`，但该文件**不在仓库中**（只存在于已打包的 zip 里），而 `$ErrorActionPreference='Stop'` 会让 `Copy-Item` 报错即中止。`README.md:15` 还声称包里有它。
**修复**：把 `使用说明.txt` 加入版本控制，或在 `build.ps1` 里先生成。

### 3. `server.js:212` — 给 `const` 重新赋值，异常时二次崩溃

第 186 行 `const encoding = ...`，第 212 行 `catch { ... encoding = "identity"; }` 给 const 赋值会抛 `TypeError`。压缩一旦抛错，catch 内再次抛错且无人捕获，同样打挂进程。
**修复**：第 186 行改为 `let encoding`。

### 4. `serve.js:39` — 前缀比较绕过导致目录穿越（已实测复现）

`filePath.startsWith(ROOT)` 只做字符串前缀判断，无目录分隔符边界。
**触发**：`/../naijiacun-main-evil/secret.txt` 解析后仍以 ROOT 字符串开头，可读取同前缀兄弟目录任意文件。
**修复**：`if (filePath !== ROOT && !filePath.startsWith(ROOT + path.sep))`。

### 5. `server/tts-worker.js:228` `/api/chat` — 开放的 LLM 代理，可被无限白嫖

`handleChat` 的 key 逻辑：`x-llm-key` 请求头 || `env.LLM_KEY`。访客不带 key 时直接用站长的 Key；且**该端点没有任何配额限制**（对比 `/api/sf-tts` 有 `bumpQuota`）。CORS 白名单只挡浏览器，服务端脚本可随意伪造 `Origin` 直连。
**风险**：任何人可无限调用消耗站长 LLM 额度。
**修复**：给 `/api/chat` 加与 SF TTS 相同的按 IP 限流；或去掉 `env.LLM_KEY` fallback，强制访客自带 key。

### 6. `js/kof.js:789-798` — 捕捉判定与 KO 不同步，输了也能判赢

`tryCatch()` 的 `setTimeout(..., 420)` 回调只检查 `Fight.on`，不检查是否已 KO / 回合结束。
**触发**：敌人残血时投球，420ms 内被 KO，`endRound("capture")` 抢先执行，把失败判成收服成功并发奖励。
**修复**：回调加 `if (!Fight.on || phase !== "fight" || roundEnded) return;`，并在 `Fight.start/finish` 里 `clearTimeout`。

### 7. `js/game2d.js:5490-5519` — 钓鱼第 8 竿后可无限刷捕捉球

第 8 竿后仅用 `setTimeout(closeFishing, 900)` 延迟关闭，`fishing.on` 仍为 true，期间重复按键继续 `fishing.rods++` 且每次 `state.balls += 1`。
**修复**：函数开头加 `if (!fishing.on || fishing.rods >= FISH_RODS) return;`，第 8 竿立即置 `fishing.on = false`。

## 评估后判定不改（避免过度优化 / 负收益）

- `js/3d-data.js`**（0.55MB base64 死数据）**：`window.N3D` 全仓库零消费者、无任何 HTML 加载它——**浏览器根本不会下载，对运行时零影响**，仅占仓库体积。考虑到删除不可逆且有历史追溯价值（旧 3D 方案的贴图残留），本轮不改。若想瘦身仓库，可自行执行 `git rm js/3d-data.js`（`scripts/gen-3d-assets.py` 可重新生成）。
- **pet3d.js 阴影贴图 **`autoUpdate=false`：`autoSpin` 默认 true，模型持续旋转，阴影本就需每帧更新；关掉会导致阴影定格错位，负收益。上一轮已做"标签页隐藏停渲染"，是这里的正确解法。
- **动作期间 **`Matrix4/Vector3/Quaternion`** 复用**：仅在大笑/愤怒等动作播放的几秒内发生，非常驻每帧路径；改动涉及骨骼数学，回归风险高于收益。
- `aimCell()`** 每帧分配小数组/Set、**`npcOnMap()`** 的 filter、kof 蓄力 Sprite 池**：均为「几个对象/帧」级别，现代 JS 分代 GC 下几乎无感，属过度优化，不改。
- `farm.js`** HUD 每 0.15s 的属性选择器查询**：6\~7 次/秒的低频路径，收益极低，不改。
