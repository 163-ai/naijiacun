# 奶家村 · 全站结构与系统优化方案

> 分析日期：2026-11-18
> 分析对象：https://github.com/163-ai/naijiacun （GitHub 当前 main）
> 参考材料：资料库中 5 份审查/数值报告（3 轮代码审查 + 2 轮数值审查）+ 数值改动包
> 审查方式：全站源码静态勘察 + 关键 P0/P1 逐条本地复现核对

## 0. 一句话结论（先说人话）

这个站不是"代码烂"，恰恰相反——模块划得清、有 CI、有测试、密钥管理规范，工程底子在业余项目里算优等生。真正的问题有两层：

1. **诊断和代码之间裂了一道"落地断层"**：资料库里 5 份报告把问题挖得很准、修法也写好了，但我逐条核对 GitHub 当前代码，**这些修复一个都没进去**。P0 那条"一个请求打挂全站"的漏洞，现在线上还开着门。
2. **"一个村"被拆成了十几个孤岛**：8 个 HTML 页面、4 个端（网页 / 站内桌宠 / 浏览器扩展 / C# 桌宠），各写各的导航、各维护一份角色表、各存一份状态。玩家眼里是同一个奶家村，代码里是十几套平行宇宙。

优化的正确顺序不是"先美化、先重构"，而是：**先止血（把已诊断的修复落地）→ 再缝合（统一导航与数据入口）→ 最后调系统（经济与成长）**。反过来做，等于在漏水的房子里搞装修。

## 1. 评判标准：先把"这游戏好玩在哪"写清楚

优化不是把代码改漂亮，是守住玩家体验。先把 fun hypothesis 和 5 条设计支柱定下来，后面每一条优化都用它们过审。

**Fun hypothesis（一句话）**：

> 把刷到过的网络热梗，认领成"我村里的村民"——用逛村、撸宠、唠嗑、种地把"看热闹"变成"过日子"。

**5 条设计支柱（不可妥协的体验标准）**：

| # | 支柱 | 一句话 | 本次诊断里被谁违反 |
| --- | --- | --- | --- |
| P1 | **一个村，不是十个孤岛** | 网页/桌宠/扩展/3D 共享同一份"村民"数据与称呼 | 4 端各自维护角色表；C# 桌宠只有 9 人无小草；game.html 完全脱离公共导航 |
| P2 | **点开就能玩，不配置也能爽** | 零依赖、免配置、永远有兜底 | 这条做得好（TTS 三档降级、聊天无 Key 有话术），保持 |
| P3 | **过日子的节奏** | 以"一天"为单位的种田循环是游戏心跳 | 每日任务靠 7 处各自惰性比对，没有统一"新的一天"处理器，节奏是靠约定不是靠机制 |
| P4 | **每个数字对得起玩家的时间** | 成长和经济要有 rationale，不虚假成长、不无限通胀 | atk 是死字段；金币只进少出；捕捉球只增不减；每天白送 300–480 金 |
| P5 | **谁都能来搭一把** | 粉丝协作（Issue/PR/提名），文档和实现要对得上 | README 项目结构只列 2 个页面（实际 8 个）；extension.html 是孤儿页；bridge 脚本是死代码 |

## 2. 🔴 头号问题：诊断成果没有落地（落地断层）

这是全站最高优先级，因为它同时踩中 P1/P3/P4 三根支柱。资料库报告写了修复方案，但**GitHub 当前代码逐条核对仍是未修状态**：

| 编号 | 报告定位 | 报告里的修法 | GitHub 现状（本次核对） | 严重度 |
| --- | --- | --- | --- | --- |
| #1 | `server.js:84` `decodeURIComponent` 无 try/catch | 包 try/catch，失败返回 null | `const decoded = decodeURIComponent(...)` 仍无捕获 → `GET /%%` 即可打挂进程 | **P0 线上可被打挂** |
| #2 | `server.js:186/212` 给 `const encoding` 重新赋值 | 改 `let` | 仍是 `const encoding = ...` + catch 里 `encoding = "identity"` → 压缩抛错时二次崩溃 | P1 |
| #3 | `serve.js:39` 前缀比较绕过目录穿越 | 加 `path.sep` 边界判断 | 仍是 `if (!filePath.startsWith(ROOT))` → 同前缀兄弟目录可穿越 | P1 |
| #4 | `js/kof.js` atk 死字段 | 伤害公式改读 atk，抽 BALANCE 块 | `dmg = mv.dmg * (1 + (a.lv - 3) * .07)` 仍只认 lv → 升级 +3 攻击是假成长 | P1（设计） |
| #5 | `js/game2d.js` 钓鱼第 8 竿 900ms 刷球/刷钱 | 开头硬拦 rods 上限、立即置 off | `if (!fishing.on) return` 后直接 `rods++`，第 8 竿到 close 之间仍可重复收 | P1 |
| #6 | `game.html` 缓存版本号 | v87→v88 / v57→v58 | 仍是 `game2d.js?v=87`、`kof.js?v=57` | 配套项 |
| #7 | LLM 代理 `/api/chat` 无配额 | 加按 IP 限流或去 fallback | （本仓库 `server/` 仅 2 个文件，线上代理在仓库外，需你确认是否已修） | P1 待确认 |

> 关键判断：**这不是"代码有问题"，而是"已有结论没被执行"。** 在动手做任何结构重构之前，必须先把这 6 条已确诊的修复合进 main——否则重构会把这些坑一起搬进新结构，返工成本翻倍。
>
> 注意一个现实风险：报告说修复"在本地副本，未 commit / 未 push"。如果那份本地副本就是你现在在用的，直接对 GitHub 裸基线动刀会和你的本地版本冲突。**所以第一步是确认哪份是真正的生产代码**，见文末选项 A/B。


## 4. 系统诊断（核心循环 / 经济 / 系统交互）

### 4.1 核心循环（游玩层）

```
每天 6:00 起床（现实≈4分钟/天，1秒=5分）
├─ 白天：锄地→浇水→播种 →（睡觉推进天数，需 wet/下雨）→ 成熟→收→卖钱
├─ 野外：高草区每移动>6单位、26%遭遇 → 拳皇式对战（60秒）
│         → 打到≤30%血扔球 → 收服/ KO 拿经验/ 败则 HP 归 35% 送回村口
├─ 每日：钓鱼8竿(+12/条)、唱戏(≥5命中+50+6×hits)、竹笋4根(+8/根)
│         、驿站委托(70~100)、奶察悬赏(50~90)、戏班(+150)、外卖(+60)、擂台首胜(+120)
└─ 睡觉：day++，体力/水/HP 回满，天气 26% 雨，各每日任务惰性刷新
```

这个循环本身是成立且好玩的（种田节奏 + 收集 + 格斗三种动机叠加）。问题出在循环背后的数值与系统耦合。

### 4.2 经济 sources & sinks（金币）

**Sources（每天稳定进账）**：

| 来源 | 单次 | 频率 | 日均上限 | 位置 |
| --- | --- | --- | --- | --- |
| 卖作物 | 萝卜44/玉米78/甜瓜132 | 反复 | 看种田量 | farm.js:16-18 |
| 掰竹笋 | +8/根 | 4根/天 | 32 | game2d.js:2563 |
| 钓鱼 | +12/条 | 8竿/天 | 96 | game2d.js:5440 |
| 唱戏 | 50+6×命中 | 1场/天 | \~98 | game2d.js:5606 |
| 驿站委托 | 70/80/75/90/100 | 1单/天 | 100 | game2d.js:4648 |
| 奶察悬赏 | 60/90/50 | 1件/天 | 90 | villagers.js:148 |
| 戏班 / 外卖 / 擂台 | +150 / +60 / +120 | 各1次/天 | 330 | game2d.js:4143/5744/5848 |
| 图鉴档位（一次性） | +60(3人)/+180(8人) | 一次性 | — | game2d.js:5897 |

**Sinks（出口）**：

| 出口 | 数值 | 问题 |
| --- | --- | --- |
| 买种子 | 20/35/55 | 卖 44/78/132 → 每棵净赚 24\~77，是"赚钱"不是"花钱" |
| 点传送锚点 | 30/40/35/45 | **一次性** 4 个点共 150，之后永久免费 |
| 累倒扣钱 | min(50, 10%gold) | 偶发，不构成稳定回收 |

**结论（经济诊断）**：每天净进账约 **300\~****480 金**，稳定出口几乎为零，**只有一次性的 150 金锚点**。这是一个典型的"source 找不到 sink"——按纵深设计，通胀不是"会不会"而是"什么时候"。金币在中期就会失去约束意义，种田/钓鱼/委托的奖励权重随之归零。

> 这不是数值调一调能解决的，是**结构缺 sink**。需要引入持续性金币出口（如装备/天赋/宠物喂养/竞技场入场费），且每个 sink 要能回答"玩家花了钱换到什么新决策"。任何新增 sink 必须配 rationale，未 playtest 的数值标 \[PLACEHOLDER\]。

### 4.3 捕捉球供需

- **Sources**：初始 8 + 奶蛙送2（一次性）+ 钓鱼≥3条送1（每天）+ 委托/悬赏送1\~2（每天）+ 戏班+2 + 外卖+1 + 图鉴档位+3/+5
- **Sink**：捕捉消耗 1/次（失败也扣）
- **结论**：每天白送多颗、没有购买渠道，出口只有捕捉 → 球必然过剩，捕捉的稀缺性和策略性消失。另 `game2d.js:5837` 有一行 `state.balls = state.balls;` 自赋值，疑似本想处理收服后的球增减却写成了空操作。

### 4.4 系统交互矩阵（intended / acceptable / bug）

| 系统 A ↔ B | 当前行为 | 判定 |
| --- | --- | --- |
| 升级 ↔ 战斗 | 升级提示"体力上限+8"，atk+3 被传入战斗但伤害公式只读 lv | **bug**（虚假成长，P4） |
| 钓鱼 ↔ 球/钱 | 第 8 竿到 close 的 900ms 窗口可重复收竿，每次 +12 金且 balls++ | **bug**（刷资源） |
| 戏班 ↔ 唱戏 | 交差强制加场，endStage 每次给钱并改写 stageDay → 同一天可拿两次赏钱 | **bug**（每日奖励破口） |
| 体力 ↔ 泡水/煮汤 | 泡水 +26（每天1次）、煮汤 +32（**无次数上限**，消耗1作物）→ 只要种得出作物就能反复回体力 | **acceptable→偏 bug**（体力约束被稀释，煮汤↔种田↔卖钱成闭环） |
| 战斗失败 ↔ 睡觉/包扎 | 败则 HP 归 35%，但睡觉/包扎/升级都回满 → 失败几乎无代价 | **acceptable**（休闲定位可接受，但削弱战斗张力） |
| 委托 ↔ 地图 | battle 类委托 map:null，用 roomState.name 比对，地图键与委托 map 值若不一致则无法完成 | **bug 风险**（耦合脆弱） |
| 存档 ↔ boot 流程 | `troupeResetIfNewDay()` 在 load 前跑，靠 `loadDone` 布尔门闩防止冲掉存档 | **acceptable**（靠约定规避，新增启动期逻辑易重踩"继续游戏变从头"） |
| dayFlags ↔ 时间 | `onceToday` 存 `"key:day"` 但从不清理 | **bug**（存档无限膨胀） |
| 重新开始 ↔ 任务状态 | `startGame(fresh)` 重置部分 day 字段，但未重置 bounty/visitOn/shootQuest 等 | **bug 风险**（新档带入旧任务） |

## 5. 优化方案（分三层，带 rationale）

### 第一层 · 止血（P0/P1，先做，不做完别重构）

| 动作 | 依据 / rationale | 验证方式 |
| --- | --- | --- |
| A1. `server.js` decodeURIComponent 包 try/catch | 单请求 DoS，已复现；修复成本 1 行，收益是全站可用性 | 起本地服务，`curl 'http://x/%%'` 应返回非 200 且进程存活 |
| A2. const encoding 改 let | 压缩抛错时二次崩溃打挂进程 | 构造异常 Accept-Encoding，进程存活 |
| A3. `serve.js` 加 `path.sep` 边界 | 前缀比较可穿越同前缀兄弟目录 | 请求 `../naijiacun-main-evil/secret.txt` 应 403 |
| A4. 钓鱼收竿开头硬拦 `rods>=FISH_RODS`、满竿立即置 off | 堵住刷钱/刷球 | 8 竿后连点，gold/balls 不再增长 |
| A5. atk 接入伤害公式 + 抽 BALANCE 配置块 | 修虚假成长，让升级 +3 攻击真实生效；配置块让后续数值可调 | 与报告一致，逐等级验证等价性后再改系数 |
| A6. `game.html` 版本号 +1 | 避免线上缓存导致模块导出不一致 | 浏览器强刷后加载新版本 |
| A7. 确认线上 `/api/chat` 是否已加限流 | 报告标注线上代理在仓库外，本仓库无法核对 | 你确认或提供代理仓库 |

### 第二层 · 缝合（P1 结构，止血后做）

| 动作 | rationale | 影响面 |
| --- | --- | --- |
| B1. 让 `game.html` / `group.html` 接入 `village.js` 公共导航 | 守住"一个村不是孤岛"；游戏页保留独立 HUD，只在外层加统一导航条 | 低：加 script + 一处 body class |
| B2. 清孤儿与死代码：给 extension.html 加入口，或并入 pet.html；删除/接通 `pet-extension-bridge.js` | 消除"文档说有、实际没有"的能力，P5 | 低 |
| B3. 收敛外观：定一份 `village.css` 为唯一公共层，其他 css 只留各页专有规则；统一版本参数 | 消除多层覆盖和缓存不一致 | **中**：需逐页比对样式冲突，建议一次一页 |
| B4. 村民数据源统一：`data.js` 为唯一 source，C# 桌宠构建期从它生成角色表 | 4 端能力递减的根源是各写 ID；生成而非手抄，才不会再漏小草 | 中：涉及构建脚本 |
| B5. 更新 README 项目结构 + 修正"共用导航"表述 | 文档是新人第一触点，对不上会直接误导贡献者 | 低 |

### 第三层 · 调系统（P2 玩法经济，最后做，且要先 paper 验证）

| 动作 | rationale | 注意 |
| --- | --- | --- |
| C1. 引入持续性金币 sink（装备/天赋/喂养/入场费，选 1） | 补上经济闭环，让每日奖励重新有意义 | sink 必须制造新决策；数值全标 \[PLACEHOLDER\]，需 playtest |
