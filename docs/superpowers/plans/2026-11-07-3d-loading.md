# 3D 展台加载优化 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Execute the approved request continuously.

**Goal:** 减少快速切换角色的无效下载及重复解析，等待时显示选中角色预览和真实下载状态，保持模型画质与全站风格。

**Architecture:** 保持现有 Three.js/GLTFLoader。通过独立 AbortController 获取当前 GLB，使用流读取下载字节，再交给现有 loader.parseAsync。缓存最近两位已解析角色，淘汰时释放资源。保留现有 loadVersion 防止过期结果覆盖当前角色。

**Tech Stack:** 原生 JavaScript、Fetch、AbortController、Three.js 0.180.0、本地 MeshoptDecoder、Playwright。

## Global Constraints

- 不改模型、纹理、音频、角色数据或原有舞台光照/相机/渲染质量。
- 只处理用户批准的取消旧请求、最近角色缓存、预览和真实进度。
- 缓存最多两个已解析模型（包括当前角色），同一待加载或已显示角色重复点击不重复请求。
- 使用原有完整模型和平面图；预览是等待提示，加载后仍可原样旋转、缩放、切视角、线框、原声及置顶。
- 已取消或过时的下载/解析不能显示错误、覆盖当前角色或进入缓存；真实失败可重试。
- 无 Content-Length 时只显示已下载字节，不编造百分比；下载完成与模型准备为独立状态。

### Task 1: 加载和缓存逻辑

**Files:** `js/pet3d.js`。

- [ ] 用带 signal 的 fetch 获取 GLB；流读取并累计真实字节，未知长度显示已下载量。
- [ ] 新选择取消上个请求；解析前后检查版本；保留非取消错误的重试流程。
- [ ] 两位 LRU 缓存；复用已解析模型，同一角色点击去重；淘汰时清理几何、材质、纹理、骨架和独占 ImageBitmap。
- [ ] 保留所有现有事件、视角、相机、声音及 PiP；处理 pagehide 中止与必要的 BFCache 恢复。
- [ ] 对接 DOM：`loading`、`loadLabel`、`loadProgress`、`loadDetail`、`modelPreview`。预览使用 `person.petImage || person.image`。
